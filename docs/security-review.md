## 자원 상한과 실패 동작

체크포인트는 인코딩 입력 8 MiB, 해제 결과 16 MiB, 토큰 200,000개, 구조 항목 총 400,000개, revision snapshot 10,000개를 넘으면 거부합니다. 문서 본문은 100,000자를 유지하며 큰 문서의 작은 수정은 기존 결과와 동일하게 계산합니다. 앞뒤 공통 부분을 제외한 두 길이의 곱이 2.5 billion을 넘는 단일 diff는 native 호출 전에 거부합니다. 엔진별 예산은 25,000회/10 million 입력 문자/5 billion 추정 작업량, refresh 전체는 100,000회/100 million 문자/50 billion입니다.

이 수치는 정확한 CPU 시간 보장이 아니며 native 호출을 실행 중간에 중단하지 않습니다. 한도를 넘는 정상 문서나 매우 큰 전체 이력도 갱신을 실패시킬 수 있습니다. 실패하면 부분 점수나 대체 정렬을 게시하지 않고 기존 정상 결과를 유지하며 오류 상태를 표시합니다. 최초 계산에서 정상 결과가 없으면 이용 불가 상태가 됩니다. 운영 문서의 크기·이력 분포는 확인하지 못했습니다.

메타데이터 인증의 재사용은 캐시마다 32바이트 digest 하나만 저장합니다. 정확한 전체 title+metadata 바이트가 동일하고 모든 행을 검증했던 경우에만 재사용하며, 바이트가 바뀌거나 검증에 실패하면 새 HMAC 확인을 거칩니다. 전역 문서별 메모리 캐시는 추가하지 않았습니다. 변경 없는 갱신에서도 generation을 잠금 안에서 확인하되 불필요한 DB 쓰기를 생략합니다.

## 배포 및 백업

1. Go 1.24.1 이상으로 `python route_go/security/build_backend.py --target linux-amd64`를 한 번 실행합니다. 다른 플랫폼은 빌드 안내의 대상을 선택합니다. 실행 시 Go는 필요하지 않습니다. Python 요구사항은 추가하지 않았습니다.
2. `app_session/security.key` 또는 `NAMU_SECURITY_KEY_FILE` 경로의 파일을 영속 보관하고 DB와 함께 안전하게 백업합니다. 여러 앱 프로세스는 같은 파일을 사용해야 합니다. 최초 생성은 완전한 32바이트 파일을 원자적으로 게시하며 기존 파일을 덮어쓰지 않습니다.
3. 최초 업데이트 때 기존 로그인 세션은 만료됩니다. 서명 없는 집계 캐시는 최초 한 번 원본 이력에서 재생하므로 시작 시 일시적인 추가 작업이 있습니다. 복구 키 이관은 시작 시 수행하며 정상 조회 경로에는 해시 연산이나 추가 쿼리를 넣지 않습니다.
4. 파일이 손실되면 새 키가 만들어질 수 있으므로 원래 백업을 복원해야 기존 해시 복구 키를 사용할 수 있습니다. 잘못된 길이나 symlink 파일은 시작을 실패시킵니다. DB 백업만으로 키를 복구할 수 없습니다. 비밀번호 로그인 및 비밀번호 salt는 기존 방식입니다.
5. 내부 Go 포트를 외부나 reverse proxy에 노출하지 않습니다. Docker는 빌드 단계에서 Go를 사용하고 최종 이미지에 Go를 포함하지 않습니다. `app_session` 볼륨도 보관해야 합니다.

새 열람 기록의 집계 기간은 24시간이고, 물리 행은 실행 중 기존 일일 관리로 삭제되므로 최대 약 48시간 남을 수 있습니다. 재시작 시에도 만료 행을 삭제합니다. 업데이트 전에 복사된 DB나 백업에 있는 과거 토큰·평문 복구 키는 소급해서 지울 수 없습니다. 이전 DB가 유출됐다고 의심되는 경우 복구 키를 새로 발급해야 합니다.

## 방어 범위와 검증 한계

DB 전체 쓰기 권한이 있는 공격자는 관리자 테이블이나 원본 이력 자체를 바꿀 수 있습니다. 이 패치는 DB-only 세션 위조·복구 키 사용·체크포인트 임의 소유권 위조를 줄이며 DB 전체 쓰기 공격을 무력화한다고 주장하지 않습니다. 과거 유효 서명 체크포인트의 rollback도 별도 DB 외부 신뢰 상태가 없으면 완전히 방지할 수 없습니다. 앱 파일/키/프로세스 환경을 읽거나 수정할 수 있는 공격자는 별도 신뢰 경계를 넘은 것입니다.

기존 비밀번호 해시 방식의 offline cracking 위험, 운영 DB 접근 통제·백업·네트워크·TLS 및 배포 설정은 변경하지 않았습니다. 살아 있는 운영 서버를 공격하거나 운영 데이터를 복사하지 않았습니다. 전체 의존성 CVE 감사도 이번 변경의 완료 근거가 아닙니다. 실제 MySQL 서버와 Docker daemon을 사용할 수 없어 해당 실행 검증은 제외되며, PyMySQL의 tuple 결과 형태는 별도 회귀 검사에 포함했습니다.

최종 회귀·격리 앱·성능 측정 결과는 커밋과 함께 제공하는 검증 보고서에 기록합니다. 성능 수치는 특정 격리 fixture의 관측값이며 모든 운영 부하에서 응답 시간이나 RAM 증가가 0이라는 보장은 아닙니다.
